## [R07.02] - 2026-09-26 12:09 AM

First-party **Hugging Face Inference Router** backend — the third cloud-provider plugin (after ZAI and OpenRouter) and the first to ship with a dedicated API Technical Reference written *before* the implementation, as the blueprint. The HF Router at `https://router.huggingface.co/v1` proxies 100+ open-weight models (Llama, Qwen, DeepSeek, Mistral, Gemma, GLM, Phi, Command-R, gpt-oss) served by ~18 partner providers (Together, Groq, Novita, DeepInfra, Fireworks, Cerebras, Replicate, Fal AI, Featherless, Baseten, Cohere, Nscale, OVHcloud, Public AI, Scaleway, WaveSpeedAI, Z.ai, HF Inference) through a single OpenAI-compatible `/chat/completions` endpoint. The HF Router differs from OpenRouter in one important way for users: it doesn't use OpenRouter's `:free` model-id suffix convention — free-tier status is determined by account credit + provider routing, so the AgentKthx `HF_FREE_ONLY` env var enforces a curated **`HF_FREE_MODEL_WHITELIST`** (31 open-weight models verified to have free-tier access via partner providers) and auto-appends the `:cheapest` routing suffix. HTTP 402 (free-tier credit exhausted) is a hard failure in strict mode (no retry — retrying burns router quota) and triggers `HF_FREE_FALLBACK_MODEL` swap in permissive mode, mirroring the ZAI plugin's 429 insufficient-balance fallback pattern at `zai.py:706-714`. The scaffold was built end-to-end against the blueprint in `docs/HUGGINGFACE_API_TECHNICAL_REFERENCE.md` (committed in R07.01); the parallel `docs/OPENAI_API_TECHNICAL_REFERENCE.md` (also R07.01) will serve the same role for the planned R07.0x OpenAI plugin. Initial scaffold shipped with suite 984 → 1024 passed. The R07.02 polish (see "### Polish — Live API Integration" below) added a further +32 tests → **1056 passed, 9 skipped, 0 failures** (+72 total new tests across the release: 71 in `tests/test_huggingface_backend.py`, 1 in `tests/test_is_cloud_attribute.py`).

### Features

- **New `huggingface` backend plugin (1685 lines)** — `agentkthx/plugins/huggingface/{__init__.py, plugin.json, huggingface.py}` implements `HuggingFaceBackend(OpenAICompatibleBackend)` with the full feature set from the API Technical Reference: HF_TOKEN Bearer auth (with `HUGGING_FACE_HUB_TOKEN` fallback for users still on the older `huggingface_hub` SDK convention); provider routing via `:fastest`/`:cheapest`/`:preferred`/`:<provider-name>` suffix on the model id (controlled by the new `HF_PROVIDER_POLICY` env var); `HF_FREE_ONLY` strict whitelist enforcement that rejects non-whitelisted models BEFORE any HTTP request is made (verified by the `test_free_only_true_rejects_non_whitelisted_model` test — 0 calls to `_make_api_request`); `HF_FREE_FALLBACK_MODEL` swap on HTTP 402 (mirrors ZAI's credit-exhaustion fallback); 429 retry loop with `Retry-After` header honor + exponential back-off schedule (5s → 10s → 20s → 40s → 80s → 90s cap with ±20% jitter, 6 retries default — mirrors OpenRouter R06.54); ReAct fallback when a partner provider rejects the `tools` field (HF-specific error patterns added: `tool use is not supported`, `tool_calls not supported on this model`, plus the TGI/llama-server form `unsupported param: tools`); reasoning-content capture for thinking-capable HF models (Qwen3-Thinking family, DeepSeek-R1, openai/gpt-oss-20b-reasoning) via the `reasoning` field on the response message (mirrors OpenRouter's R06.53 streaming capture); context-length 400 recovery via the shared `OpenAICompatibleBackend._handle_context_length_400` helper (ARCH-03 R06.57 — HF Router's error format matches the base-class default regex patterns, so no override is needed); JEV dispatch via `_jev_call_completions()` routing through `self.generate()` so auth + 429 retry + `HF_FREE_ONLY` are preserved; both canonical (`huggingface`) and alias (`hf`) `--backend` values work end-to-end (verified by `agentkthx models --backend hf` returning 154 models from the live router API). The 1-hour model-list cache (mirrors OpenRouterBackend) prefers live `/v1/models` data for `context_length` and per-provider `max_completion_tokens`, falling back to a 31-model static catalog `HF_MODELS` when the API is unreachable.

### Bug Fixes

- **`get_backend_choices()` silently dropped plugin-registered aliases** (`agentkthx/backends/__init__.py`) — the function called `pm.list_backend_names()` which only returns canonical names registered via `register_backend()`. Aliases declared in a plugin's `plugin.json` `cli_flags."--backend"` array (e.g. the huggingface plugin declares `["huggingface", "hf"]`) were silently dropped from the CLI's argparse choices — `agentkthx models --backend hf` failed with `invalid choice: 'hf'`. Now delegates to `pm.get_backend_choices()` which reads the `cli_flags` field directly, so all declared choices surface in the argparse choices list. The fix benefits any future plugin that wants to register an alias (previously required editing `backends/__init__.py` to add the alias to the native list — the wrong layer for a plugin-registered name).
- **`find_plugin_for_backend()` chicken-and-egg on aliases** (`agentkthx/plugins/_loader.py`) — the reverse-mapping (backend name → plugin name) only checked `manifest.provides.backends` (the canonical name). When `_ensure_plugin("hf")` was called for the alias, it failed to find a matching plugin and fell back to `plugin_name = "hf"` (which doesn't exist as a plugin directory), raising `ValueError: Cannot load backend 'hf'. Plugin 'hf' not found`. The alias map (`_backend_aliases`) is populated only AFTER `register()` runs, but `register()` runs only AFTER `_ensure_plugin()` resolves the name — classic chicken-and-egg. Now also checks `manifest.provides.cli_flags."--backend"` so aliases declared in the manifest resolve to the right plugin BEFORE the plugin's `register()` has had a chance to call `register_backend(alias_of=...)`.
- **Agentic-loop streaming path bypassed `HF_FREE_ONLY` upfront check** (`agentkthx/plugins/huggingface/huggingface.py`) — the agentic loop calls `generate_completions_stream()` directly for cloud backends (`is_cloud=True`), NOT `generate_stream()`. The original scaffold only overrode `generate_stream()` (which checks `HF_FREE_ONLY` upfront and raises `RuntimeError` for non-whitelisted models). The inherited base-class `generate_completions_stream()` skipped the whitelist check and made HTTP requests for paid models — defeating the purpose of `HF_FREE_ONLY` (which is to prevent accidental paid API calls). Caught via live CLI smoke test (`HF_FREE_ONLY=true agentkthx run --backend hf --model anthropic/claude-3.5-sonnet` reached the API layer and got a 401 instead of being rejected upfront). Mirrors the ZAI backend's pattern (zai.py:756-785 overrides BOTH `generate_stream()` AND `generate_completions_stream()`). Added the missing override; verified via CLI smoke test (paid model rejected in 0ms with 0 HTTP requests made).

### Polish — Live API Integration

After the initial scaffold shipped and VTSTech ran the first live `agentkthx chat --backend hf --model openai/gpt-oss-20b --stream --think` session successfully (banner: `R07.02-8a62f7a`, 154-model cache populated, reasoning content captured via the new `reasoning` field, footer token-tracking live `↑20 ↓8`), a direct probe of `GET https://router.huggingface.co/v1/models` revealed that the live API response shape is **much richer** than the technical reference documented. The initial `_parse_hf_model()` looked for flat model-level `pricing.prompt` / `pricing.completion` fields that don't exist on the live API — the real shape nests pricing under a per-provider `providers[]` array with `{input, output}` keys, plus a per-provider `is_free: bool` flag (the gold we wanted but didn't know existed until the live probe). As of 2026-09-26: `is_free` is `false` for all 336 combos even with auth — HF's free-tier model is purely credit-based ($0.10/mo credit at partner provider rates, matches the May 2026 klymentiev report). The polish captures the richer shape anyway, so when HF flips any combo `is_free=true` tomorrow (sponsored/promo window), AgentKthx auto-picks it up with zero code change. VTSTech's live `whoami-v2` response confirmed the token is valid (`name: VTSTech`, `email: veritas@vts-tech.org`, `auth.accessToken.role: read`, `canPay: false` → free tier, `billingMode: prepaid`, `periodEnd: 1790812800` → Sept 30 2026, `isPro: false`) — exactly the user profile that benefits from `HF_FREE_ONLY` enforcement. The polish adds a per-user free-tier probe so the same protection auto-enables even when the user did NOT set the env var explicitly.

- **`_parse_hf_model()` rewritten to capture the live per-provider shape** (`agentkthx/plugins/huggingface/huggingface.py`) — the parser now extracts and aggregates the per-provider fields documented in the live `/v1/models` response: `cheapest_input_per_1m` and `cheapest_output_per_1m` (USD per 1M tokens, MIN across providers — for surfacing "via $X/1M" in the model listing later, Change #4 deferred), `any_free_provider` (OR of `is_free` across providers), `any_supports_tools` / `all_support_tools` (tool-support signals per provider), `any_supports_structured_output`, `owned_by` (the model's authoring org), `provider_count`. Top-level `context_length` and `max_completion_tokens` are aggregated as the MAX across providers (best-case budget — the actual budget per request depends on which provider the router picks under `:fastest` routing, which is non-deterministic). The full raw `providers[]` array is preserved on the parsed model under the `providers` shortcut key (for `_is_free_model_live()` consultation) and `model_data` (full original response for forward-compat — any future field the API adds is available without code change). Verified live: `Qwen/Qwen3-4B-Thinking-2507` now shows `256K` context in `agentkthx models --backend hf` (the per-provider max from the live API) vs the previous `32K` from the static catalog — the live API is now correctly consulted.

- **`_is_free_model_live()` instance method — live `is_free` auto-detection** (`agentkthx/plugins/huggingface/huggingface.py`) — supplements (does NOT replace) the static `HF_FREE_MODEL_WHITELIST` with live API `is_free` flag consultation. Returns True if EITHER (a) the model is in the static whitelist (fast path, no instance state needed — the documented ground truth when `/v1/models` is unreachable), OR (b) the live API cache has any provider on this model flagged `is_free=true`. As of 2026-09-26: `is_free` is `false` for all 336 combos even with auth — but HF can flip this true at any time for sponsored/promo windows, and this method auto-picks that up with zero code change. Strips the provider suffix (`:fastest` / `:cheapest` / `:preferred` / `:<provider-name>`) before lookup — the suffix is a routing hint, not part of the model identity. Falls back gracefully if cache is empty (returns False, falls back to static-whitelist-only consultation). The 9 call sites (`generate`, `generate_stream`, `generate_completions_stream`, `_make_api_request` 402 path × 2, `_iter_sse_lines` 402 path × 2, `list_models` filter) all updated to use the new live method.

- **`_probe_whoami()` + `_resolve_free_only_mode()` — token validation + free-tier auto-detection** (`agentkthx/plugins/huggingface/huggingface.py`) — on every `__init__`, the backend now probes `https://huggingface.co/api/whoami-v2` to (a) validate the token before the first chat call (catches typos / expired tokens early with a clear "your HF_TOKEN is invalid or expired" path instead of a confusing 401 mid-conversation), and (b) detect free-tier users via `canPay=False`. The probe is best-effort — failures (network down, 401 with bad token, 5xx) are swallowed; `_user_info` stays None and the backend still works (paid inference will surface its own 401 at request time). Token-role check is honest: a `read`-role fine-grained token (the default) is enough for `whoami-v2`; higher-role endpoints (`/api/inference-providers`, `/api/billing/usage`) require `write` or `admin` role and return 401 for `read`-role tokens — we don't need them anyway. `_resolve_free_only_mode()` resolves the effective `HF_FREE_ONLY` behavior with explicit-env-var > whoami-auto-detect > module-constant fallback: explicit `HF_FREE_ONLY=true` → strict (no auto-detect, respects explicit opt-in); explicit `HF_FREE_ONLY=false` → permissive (opt-out — skips whoami entirely); unset → auto-detect: `canPay=False` → strict + one-time stderr warning ("Detected free-tier account, $0.10/mo credit at partner provider rates. Auto-enabling HF_FREE_ONLY whitelist. Set HF_FREE_ONLY=false to override."), `canPay=True` → permissive; whoami unreachable → fall back to module-level `HF_FREE_ONLY` constant. The env-var check reads `os.environ` directly (not the parsed bool constant) so we can distinguish "user set the var" from "default false" — critical for the auto-detect path. VTSTech's account (`canPay=false`) gets auto-enabled whitelist protection + the warning even without setting the env var explicitly; if he later adds a billing card, the auto-detection flips to permissive with no code change.

- **`_apply_provider_policy_live(backend, model_id)` helper + `force_cheapest` parameter** (`agentkthx/plugins/huggingface/huggingface.py`) — the module-level `_apply_provider_policy(model_id, force_cheapest=False)` now takes an optional `force_cheapest` parameter (replaces the old module-level `HF_FREE_ONLY` check). The new `_apply_provider_policy_live(backend, model_id)` instance helper passes `force_cheapest=backend._free_only_effective` so the auto-detected free-tier mode is honored everywhere — `:cheapest` is auto-appended to model ids even when the user did NOT set `HF_FREE_ONLY=true` explicitly. The 9 instance call sites (`generate`, `generate_stream`, `generate_completions_stream`, `_make_api_request` 402 path × 2, `_iter_sse_lines` 402 path × 2) all updated to use the live helper. Backward-compat preserved: the old `_apply_provider_policy(model_id)` form still works (defaults `force_cheapest=False`, falls back to the module-level `HF_FREE_ONLY` constant — existing tests untouched).

- **Once-per-process warning flag** (`agentkthx/plugins/huggingface/huggingface.py`) — the free-tier stderr warning is now process-scoped via a class-level `_free_tier_warning_emitted: bool = False` flag. The CLI may instantiate `HuggingFaceBackend` twice in one command (once for `_probe_backend` feature discovery before argparse, once for the actual `cmd_models` / `cmd_chat` invocation), and the warning was firing twice — confusing the user about whether something was wrong. The flag is checked before the print, set to True on first emission, so subsequent instances in the same process skip the print but **still enforce the whitelist** (return True). Class-level (not instance-level) so all instances share the same flag. Caught during live CLI testing of the auto-detection (`unset HF_FREE_ONLY && agentkthx models --backend hf` showed the warning twice).

- **`_probe_whoami()` early-return resets `_user_info` to None** (`agentkthx/plugins/huggingface/huggingface.py`) — when `api_key` is empty, the method bailed out early via `return` but didn't reset `self._user_info = None`, leaving stale state from a previous (failed) probe. Surfaced by `test_probe_skips_when_no_api_key` — the test set `_user_info = "stale-value"` then called `_probe_whoami()` with empty api_key and expected `_user_info` to be None, but it stayed as "stale-value". Fixed: the early-return path now explicitly sets `self._user_info = None` before returning, so `_resolve_free_only_mode()` falls back cleanly to the module constant.

### Bug Fixes

- **Version git-suffix no longer misattributes foreign repositories (audit ROB-07)** — `_get_git_short_hash()` walked up to 5 parent directories looking for *any* `.git`, so a pip-installed AgentKthx that merely sat inside the *user's* project repo reported that repo's hash in its version string (observed in the wild: `0.7.00-db152d9`). ### Maintainability

- **Strip UTF-8 BOMs from `agentkthx/skills/` + enforce no-BOM invariant (audit MAINT-06)** — 15 .py files under `agentkthx/skills/` (the package's `__init__.py` plus 14 files under `skill-creator/scripts/`) began with a UTF-8 byte-order mark (EF BB BF). Four new regression tests in `tests/test_no_bom_in_skills.py` assert (a) no shipped `.py` under `skills/` begins with the BOM, (b) the packager rejects a BOM-bearing skill, and (c) the packager still accepts clean skills.
