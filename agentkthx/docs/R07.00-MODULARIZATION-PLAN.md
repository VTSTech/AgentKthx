## 1. Problem Statement

After R06.59's surgical helper extractions, `agent.py` (3466 lines) and `cli.py` (4270 lines) are still monolithic. The two largest methods — `_run_core` (~614 lines) and `_run_core_streaming` (~532 lines) — remain difficult to navigate, and `cli.py`'s 15 `cmd_*` entry points are all crammed into one file.

**This is NOT a "split for the sake of splitting" plan.** Every extraction below has a concrete maintenance pain it solves.

## 3. Guiding Principles

1. **No behavioral changes.** R07.00 is pure reorganization. Every test in the existing 933-test suite must pass unmodified.
2. **One concern per module.** If a function's docstring says "and also", it's a candidate for splitting.
3. **Preserve import paths.** `from agentkthx import Agent` and `from agentkthx.cli import main` must still work. Public API is frozen.
4. **Incremental, not big-bang.** Each phase ships independently, tests green, ready to push. No "finish all 6 phases or nothing" branching.
5. **Extract, don't rewrite.** Move code verbatim — no logic changes, no "while I'm in here" cleanups. Those go in separate commits.
6. **The 8 Phase 1-4 helpers are the template.** They proved the pattern: extract → wire call site → test → commit.

## 4. Extraction Plan

### Phase 5: Split `_run_core` and `_run_core_streaming` (R07.00 flagship)

**Goal:** Eliminate the last major duplication — the ~150-line per-tool-call loop body that Phase 4 deliberately skipped.

**New module:** `agentkthx/core/agentic_loop.py`

Extract:
- `_run_loop_iteration(generate_fn, prompt)` — the unified agentic loop body (the Phase 5 holy grail from the original `refactor.zip` plan)
- `_execute_single_tool_call(tc, ...)` — the inner per-tool-call handler (the #4 candidate from the earlier analysis)
- `_process_tool_result(result, ...)` — post-execution memory + error-recovery tracking

**Risk:** Medium-high. The loop body has streaming-specific inline printing (R06.55) + compaction-between-calls (R06.58) with multiple `break`/`continue` exit paths. Mitigation: parameterize via a `LoopCallbacks` dataclass with optional `on_tool_executed` / `on_compaction_needed` hooks.

**Estimated savings:** ~140 lines deduped, `_run_core` and `_run_core_streaming` each shrink to ~30-line thin wrappers (matching the original `refactor.zip` vision).

**Tests:** The existing 933 tests cover both paths — they're the safety net. Add 15-20 new tests for `_run_loop_iteration` in isolation.

### Phase 6: Extract streaming machinery

**New module:** `agentkthx/core/streaming.py`

Extract from `agent.py`:
- `_generate_stream()` (~355 lines)
- `_generate_stream_chunks()` (~90 lines)
- `run_stream()` (~250 lines) — the OpenResponses SSE generator
- `_iter_sse_lines()` helper

**Why:** These 4 methods are ~700 lines of streaming-specific code that has nothing to do with the agentic loop logic. They're a self-contained subsystem (SSE parsing, chunk accumulation, delta printing) that can be tested independently.

**Risk:** Low. No call-site changes — just `from .core.streaming import StreamingMixin` and the Agent class inherits it.

**Estimated savings:** ~700 lines moved out of `agent.py` → `agent.py` drops from 3466 to ~2766.

### Phase 7: Extract compaction subsystem

**New module:** `agentkthx/core/compaction.py`

Extract from `agent.py`:
- `_check_compaction()` (~75 lines)
- `_snapshot_running_tokens()` (~25 lines)
- The token-tracking block from `_run_core_streaming` (~30 lines)

**Why:** The R06.58 compaction fix touched 5 files. If a future compaction bug surfaces, the relevant logic is currently scattered across `agent.py` (3 sites) + `core/memory.py` (`compact_messages`). Consolidating into one module makes the subsystem addressable.

**Risk:** Low. Pure move, no logic change.

**Estimated savings:** ~130 lines moved out of `agent.py`.

### Phase 8: Split cli.py into a package

**New package:** `agentkthx/cli/` (directory)

Split `cli.py` (4270 lines) into:

```
agentkthx/cli/
├── __init__.py          # re-exports main(), create_parser() — public API preserved
├── parser.py            # create_parser() + add_*_args helpers (~550 lines)
├── agent_factory.py     # _build_agent() + _init_acp() (~250 lines)
├── footer.py            # footer machinery shared by cmd_chat + cmd_agent (~200 lines)
├── commands/
│   ├── __init__.py
│   ├── chat.py          # cmd_chat (~1100 lines → ~600 after footer extraction)
│   ├── agent.py         # cmd_agent (~440 lines → ~200 after footer extraction)
│   ├── run.py           # cmd_run (~150 lines)
│   ├── test.py          # cmd_test (~650 lines)
│   ├── models.py        # cmd_models (~600 lines)
│   ├── config.py        # cmd_config + _print_config_summary (~250 lines)
│   ├── plugins.py       # cmd_plugins (~190 lines)
│   ├── soul.py          # cmd_soul (~190 lines)
│   ├── turbo.py         # cmd_turbo (~250 lines)
│   ├── version.py       # cmd_version + cmd_update (~300 lines)
│   ├── sessions.py      # cmd_sessions (~100 lines)
│   ├── modelfile.py     # cmd_modelfile (~100 lines)
│   ├── skills.py        # cmd_skills (~100 lines)
│   └── tools.py         # cmd_tools (~20 lines)
└── utils.py             # _print_agent_steps, resolve_model_pattern, etc. (~300 lines)
```

**Why:** `cli.py` is the single biggest maintenance pain point. A bug in `cmd_turbo` requires scrolling past 3000 lines of unrelated code. Each `cmd_*` function has its own imports, its own helpers, its own concerns — they're already logically modular, just physically co-located.

**Risk:** Low-medium. The main risk is import cycles — `commands/chat.py` imports `agent_factory.py` which imports `agent.py`. Mitigation: keep `cli/__init__.py` as the single entry point that wires everything; use lazy imports for cross-command dependencies.

**Public API preserved:** `from agentkthx.cli import main` still works (via `cli/__init__.py` re-export).

**Estimated savings:** `cli.py` goes from 4270 lines to 0 (deleted), replaced by ~15 files averaging ~280 lines each. No line-count savings — but navigation/maintenance cost drops dramatically.

## 7. Non-Goals

- **No new features.** R07.00 is reorganization only.
- **No API changes.** `Agent`, `Agent.run()`, `AgentRun`, `main()`, `create_parser()` all keep their signatures.
- **No performance optimization.** If extraction reveals a perf opportunity, file it as R07.01.
- **No test refactoring.** Existing 933 tests stay as-is. New tests are added per-phase for new modules.
- **No documentation rewrite.** `docs/ARCH.md` gets a single section update noting the new module layout.

## 8. Rollback Strategy

Each phase is a single commit. If a phase introduces a regression:
1. `git revert <phase-commit>` — instant rollback
2. No data migration, no config change, no user-visible difference
3. Tests are the canary — if 933 tests pass, the phase is safe

## 10. Open Questions

1. **Phase 5 callback design:** Should `_execute_single_tool_call` use a `LoopCallbacks` dataclass, or should the streaming path subclass a `StreamingAgenticLoop(AgenticLoop)`? Dataclass is simpler; subclass is more OOP. **Recommendation: dataclass** — matches the existing `enable_compaction_recovery` flag pattern from Phase 1.

2. **Phase 8 import strategy:** Should `cli/commands/chat.py` import `Agent` directly, or go through `cli/agent_factory.py`? Direct import is simpler; factory indirection allows future DI. **Recommendation: direct import** — YAGNI on DI.

3. **Should `core/agentic_loop.py` be a Mixin or a standalone module of functions?** Mixin lets `Agent` inherit `_run_loop_iteration` as a method; standalone requires passing `self` explicitly. **Recommendation: Mixin** — preserves `self._run_loop_iteration(...)` call sites, zero diff to callers.
